### 認可

**1. 未登録と認可なしの扱いが矛盾している**（`spec.md:24`、`spec.md:30`、`acceptance-matrix.md:8`）

### scope と順位

**3. 適格でない同順位の候補を飛ばすと、自動フォールバックになる**（`spec.md:38` と `spec.md:11` の衝突）
- 問題: 順位は「適格候補」の中で付けることになっています。このため、順位1の候補が A（適格）と B（unknown）なら A が選ばれます。順位1が unknown だけで順位2に適格な候補があれば、same_repository では順位2が選ばれます。本来の相手は観測が遅れているだけかもしれません。それでも別の会話が選ばれ、`spec.md:11` が除外した「別会話への自動フォールバック」になります。
- 修正: 順位は、scope 内の認可済み候補で先に決めます。最小順位の集合に unknown、stale、invalid、取得失敗が1件でもあれば選択しません（例: `blocked_unobserved`）。下の順位にも降りません。集合から除いてよいのは、信頼した観測で停止が確定した候補だけです。matrix に2行足します。「順位1の適格1件と stale 1件」と「順位1が stale で順位2が適格」です。

**4. scope と順位の対応、Git 外、detached、unborn の順位が決まっていない**（`spec.md:18`、`:20-21`、`:38`、`matrix:15`）
- 問題: matrix の15行目は状態を保つとしか書いていません。どの順位に入れるかは実装者任せになっています。
- 推奨する規則:
  - scope と順位の対応: current_work は順位1だけ。same_repository は順位1〜2。any_registered は順位1〜3。
  - Git 外: 双方が Git 外で、論理 workspace の実 path が一致すれば順位1。それ以外は順位3で、same_repository の対象外。
  - detached: branch の代わりに HEAD の一致を条件にする。片方だけ detached なら順位1にしない。
  - unborn: 双方が unborn で、同じ symbolic ref を指すときだけ一致とする。
  - 取得失敗: 順位を付けず、修正3の規則で選択を止める。

### 観測を信頼できるか

**5. 作業場所 path の出所が自己申告のまま**（`spec.md:17`、`:39`、`Plans.md:10`、`:23`）
- 問題: Git は claudex 自身が実行するので、Git の観測は信頼できます。ただし、どの path を観測するかは bootstrap の申告で決まります。申告された cwd は、bootstrap に書かれた online と同じ自己申告です。正しい path の Git を読めても、その会話がそこで作業している証拠にはなりません。
- 修正: 観測アダプターの返り値に native の cwd を含めます（`{native_id, generation, cwd, observed_at, source}`）。順位の判定には、アダプターが観測した cwd を起点にした Git 観測だけを使います。申告 path は `declared_workspace` として表示用に分けます。P1 はアダプター未接続なので結果は unknown のままで、変わりません。P2 に渡す契約の穴を塞ぐための修正です。

**6. read-only git の実装条件が足りない**（`Plans.md:10`）
- `git status` は既定で index を更新し、`index.lock` を取ります。相手の会話が同時に `git commit` すると、lock の衝突で失敗する可能性があります。これは「read-only」と言えません。
- repo 設定の `core.fsmonitor` があると、git 実行時に任意のコマンドが起動します。
- 継承した `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE` があると、別の repo を観測してしまいます。
- 応答しない git があると、serve ループが止まります。
- 修正: `--no-optional-locks`、`-c core.fsmonitor=false`、`GIT_*` 環境変数の除去、呼び出しごとの timeout（超えたら unknown）を入れます。dirty に untracked を含めるかも決めます。matrix には「観測の前後で `.git/index` の mtime が変わらない」「`GIT_DIR` を設定しても対象 path を観測する」「timeout なら unknown」を足します。

### CLI プロセスの寿命と binding
