# セッション互換通信の仕様案

> 2026-10-04 に claudex から seamless へ改名した（独立リポジトリ）。本文の claudex、`~/.claudex`、実行したコマンドは記録当時の旧名のまま残す。

Updated: 2026-10-01 JST
Status: 実会話とDesktopの方式検証済み。以下は製品実装で維持する仕様。

目的: 同じMacの登録済みCodexとClaudeの元の会話を、自然言語で一覧、読み取り、送信、返信できる。
共通MCP窓口を追加する。純正toolの差替えや他社sessionの偽装登録はしない。
片方だけの機能は共通化しない。agmsgはforkしない。共有SQLiteを作らない。

## 必須条件

1. session IDと実行体を維持する。送信のたびに別プロセスへresumeしない。
2. 両方から相手の登録済み会話の本文を読める。元のmessage ID、役割、取得時刻を返す。
3. 両方向の依頼と返信を元の会話へ届ける。peer/tool由来を本人の指示に格上げしない。
4. idleとbusyで通知を受けられる。busy中の実行を破壊しない。
5. senderとrecipientを登録済み接続から確定。不存在を空会話に偽装しない。
6. 観測した配送段階だけを示す。unknown時の自動再送と無限返信をしない。
7. 本文の正本は元製品。中継は接続情報と送信中の相関だけを保持する。
8. CLI、既存Desktop、fixtureの試験結果を分ける。未対応箇所を隠さない。

小型試験と実装順序はPlans.md。旧案のSQLite/Channels優先案と承認待ち停止は本案へ更新。
完成条件: Plans.mdの製品受入条件10項目が、実装コードに対する試験と別家系の独立判定を伴って合格する。方式検証の完了と、製品実装の完成を区別する。

readの共通範囲は可視テキストとpeer由来。画像、音声、添付実体、思考の変換は含めない。Desktopは対応版を照合し、未対応版で送信を継続しない。1messageと1turnを同一視しない。重複は共通write経路でnative配送前に止める。
