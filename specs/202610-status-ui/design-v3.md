# 帯 第3版の情報設計

更新: 2026-10-05 JST
状態: 実装済み（見本 out/design-v3/mock.html に立花さんが OK。実画面の確認待ち）
元: 立花さんの指摘（2026-10-05）「他セッションとのやりとりの要素が少なすぎる。これなら you-should-know でよくない？」「今何してるのかの表示が公式のスピナーと被っている。マクロ、メゾの視座で」。
前版: [design-v2.md](design-v2.md)。この文書が変えたところだけを書く。原則、色、印、開閉は第2版のまま。

## 決めたこと

| 点 | 第2版 | 第3版 | 理由 |
|---|---|---|---|
| 1行の左 | 目的 › 段 n/m › 今の一手 | 目的 › 段 n/m。計画が無いときは作業の局面 | 今の一手はアプリのスピナーが出す。帯は「何のために、どの段か」を受け持つ |
| 作業の局面 | なし | 直近5回の道具の呼び出しで一番多い種類（同数は新しい方）。調べている、書いている、確かめている、相手とやりとりしている、子エージェントに任せている、段取りを決めている。道具の前は「指示を読んでいる」「考えている」、返事を書く間は「まとめている」 | 1回ごとに変わる一手より、数手の流れの方がメゾの粒度に合う |
| 経過時間 | 今の一手の時間 | このターンの時間（承認と質問の待ちは、待ち始めからの時間） | 左が目的と段になったので、時間もそれに合わせる |
| 1行の右 | 会社のロゴと ↑n(n) ↓n(n) | ロゴ、一番大事なやりとりの言葉、↑↓の数 | seamless の帯である理由を1行に出す。数だけでは何が起きているか読めない |
| 右の言葉の選び方 | なし | まだ読んでいない受信（「返信が届いた」「依頼が届いた」、緑）を先に。無ければ一番新しい送信の状態: 送った n分、届いた・未読 n分、読んでいる n分（橙）、返信あり（緑、30分まで）、! 届かなかった（赤） | 人が動くべきものを先に出す。進行中は経過時間で滞りが分かる |
| 通知 | なし | 2回目以降の照会で変化を見つけたらトースト: 依頼を読み始めました、依頼に返信しました、返信が届きました、依頼が届きました、依頼が届きませんでした。1回の照会で3件まで | 帯を見ていなくても気づける。最初の照会は基準にするだけで知らせない |
| 開いた状態の順 | 問題、目的、計画、手順、子エージェント、やりとり | 問題、やりとり、目的、計画、手順、子エージェント | やりとりが主役 |
| やりとりの欄 | 相手ごとに1行（最新の状態だけ） | 相手ごとに見出し（会社、作業場所、動いている／止まっている）と、新しい依頼3件。各依頼は本文の冒頭（送った依頼だけ）と、送った › 届いた › 読んでいる › 返信 の段を時刻つきで | どこで止まっているかが一目で分かる |
| 受け取った依頼の本文 | 出さない | 出さない（立花さん判断 2026-10-05） | 照会は本文を持たない決まり。変えるなら本体の変更と判定を別に行う |
| 照会の失敗 | 相手の行を灰色の「未確認」 | 相手の見出しは残し、依頼ごとに「状態は未確認」。右の言葉は出さない | 古い状態を今の状態のように見せない |

## 材料

- 段ごとの時刻: 照会（`src/cli.ts band`）の `requests[].stages[].at`。
- 相手が動いているか: 照会の `candidates[].status`（online なら「動いている」）。
- 返信の見分け: 受け取った依頼の時刻が、こちらの送信の返信の時刻と同じなら返信。受け取った依頼は返信先の id を持たないため。
- 照会の間隔は60秒のまま。seamless の道具を使った後と、依頼を受け取った後にも照会する。
