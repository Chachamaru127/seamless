## 原則

1. 一目で「今なにを、何のために」が分かる。読むのは1行だけ。
2. 静かなときは静かに。色と動きは、人が動くべきときだけ使う。
3. 細部は隠すが、1クリックで全部見える。
4. Claude アプリの一部に見える。黒い板を置かず、アプリの地と文字色に合わせる（ライトとダークの両方）。

## 3つの粒度（閉じた1行の中身）

| 粒度 | 意味 | 出どころ | 例 | 見た目 |
|---|---|---|---|---|
| マクロ | このターンの目的 | 立花さんの指示（turn.start の本文）を短く | 帯を仕上げる | 薄い色。先に切り詰める |
| メゾ | 計画の今の段と進み | TodoWrite の作業中の項目と「n/m」 | 見出しを直す 3/7 | 通常の色 |
| ミクロ | 今の一手 | 道具の呼出し（Bash の description、ファイル名）、考えている、返事を書いている | register.tsx を編集 | 太字。最後まで残す |

並べ方: `● マクロ › メゾ n/m › ミクロ · 経過`。幅が足りないときは、マクロ、メゾの順に切り詰め、ミクロと経過は残す。作業一覧（TodoWrite）が無いターンはメゾを出さない。

## 右側（通知）

2026-10-05 立花さんの指示「↑1 ↓2(1) のように、送信できたら数、届いたか分からない、まだ読んでないときは (n)。問題があれば !、開いたらエラー詳細」で決めた。

- 会社ごとに、ロゴ（灰）と `↑送った数(未確認の数)` `↓受け取った数(まだ読んでいない数)`。0 の向きは出さない。括弧は 0 なら出さない。
- 未確認: 送った依頼で、既読（処理開始か返信を観測）でも拒否でもないもの。まだ読んでいない: 受け取った依頼で、最後のターンが始まった後に届いたもの。
- `!`（赤）: 依頼が届かなかった（拒否）か、帯の照会が失敗した。開くと先頭の「問題」の欄に、相手、時刻、届かなかったこと、または照会の失敗の理由を出す。拒否の理由は照会で取れないので出さない。
- 利用枠と文脈の使用率は出さない（Desktop が別の欄で出している）。

## 進み（閉じた状態）

進みの線は出さない（「3/7」の文字で足りる。両案とも線は雑音だった）。n/m は「作業中の項目が何番目か」。作業中が無いときは済んだ数。閉じた1行と開いた見出しで同じ数え方。

## 決めたこと（実装で確定）

| 点 | 決定 | 理由 |
|---|---|---|
| 太字 | 目的（マクロ）を太字、今の一手は細字 | 今の一手は1秒ごとに変わる。そこを太字にするとちらつく。動かない目的を錨にする（Ask Pro の案から） |
| 印 | 14px の Svg（作業中 紫、要対応 オレンジ、完了 緑、エラー 赤、中断 灰） | 文字の印より形で見分けやすい。Svg は alt が空だと Desktop が描かない（撮影で確認）ので、全部に alt を付ける |
| 地 | 塗らない | Desktop のカードの中に描き、黒い板を置かない |
| 文字色 | テーマの色の名前（text、inactive、subtle、success、warning、error） | ライトとダークを Desktop が描き分ける（ライトは撮影で実測） |
| 開閉 | 外枠ありの Button（▸ ▾） | plain と dimColor は暗い地に溶けた（撮影で確認） |
| 開いた状態 | 2列（見出し、中身）。問題、目的（100字）、計画（6件の窓、作業中を含む）、計画が無いときは手順（直近5件、考えた／返事を書いたは除く）、子エージェント（2つ以上）、やりとり | 雑音を除き、判断に要るものだけ |

## 開いた状態（クリックで広がる）

上から:

1. 目的: 指示の全文（2行まで）。
2. 計画: 作業一覧を ✓ 済み、● 作業中、○ 未着手 で。各項目の所要時間。
3. 手順: 直近の手順（印と所要時間）。今の一手は紫の ●。
4. 子エージェント: 名前と今の一手。
5. やりとり: 相手ごとの行（ロゴ、相手、作業場所、本文の冒頭、状態）。
6. 利用: 文脈の使用率、利用枠の残り（出どころは $.session.usage()）。

you-should-know に倣う点: 入力欄の上の短い1行、開くと詳しい中身、閉じるとすぐ戻る。言い方を変えるボタン（平易に、短く、詳しく）は、この帯には付けない（帯は表示だけ。AC6）。

## 色

- 地: 塗らない（Claude アプリの入力欄の上の地をそのまま使う）か、テーマに追従する色。黒い板は使わない。
- 文字と印: テーマの色の名前（text、inactive、subtle、success、warning、error、claude など）で指定し、ライトとダークで自動で切り替わるようにする。Desktop でどう描かれるかは、確認用の行 G〜J の撮影で確かめる（2026-10-05）。
- 紫の作業中の点、緑、オレンジ、赤は、両方の地で見分けられる明るさにする。

- 地を塗らない帯と、テーマ色の外枠の見え方（H）。
- 進みの線（Svg と、幅を割合で指定した Box）と、点の明滅（Svg のアニメーション）が描けるか（I）。
